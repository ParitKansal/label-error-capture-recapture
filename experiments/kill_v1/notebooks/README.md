# How to run these on Colab

Generated by `../src/make_notebook.py`. Each notebook embeds the source it needs, so upload the `.ipynb`
and nothing else. Everything writes to `MyDrive/label_error_crc/kill_v1/` and resumes from what is already
there, so a disconnect costs one chunk, not a run.

**Do not start any of this until `PREREG.md` is approved and committed.**

Budget: about **4.1 A100-hours** expected, **7.7** worst case uncut, against a hard stop of **7**
(`PREREG.md` §10). Colab bills session time, not GPU use, so **close each session the moment its notebook
prints DONE**.

Step 2 is four **separate Colab sessions running at the same time**, one per notebook. They do not talk to
each other; they write to different files on the same Drive folder.

## Before you start

1. **Hugging Face token for Llama.** `meta-llama/Meta-Llama-3-8B-Instruct` is gated. Accept the licence on
   the model page, make a read token, and in `judge_llama3.ipynb` add it as a Colab secret named `HF_TOKEN`
   (key icon in the left sidebar) with notebook access on. Without this, step 2's Llama notebook fails at
   load. Nothing else is gated.
2. **Check the GPU you actually got.** The first cell prints the device name, compute capability and
   memory. Expect `A100`, `(8, 0)`, `~42 GB`. If you got a T4 or a V100, stop — the models will not fit.
3. **Watch the prompts/s line.** Each judge prints a rate and an ETA every 512 rows. If the four judges
   together project past 4.5 A100-hours, stop and report rather than cutting scope (`PREREG.md` §10).

## What each one prints when it is done

- judges: `JUDGE PASS DONE` then `PROBABILITY PASS DONE`
- modern arm: `MODERN ARM DONE`
- analysis: the empirical coverage line, then the four GO conditions

## If something breaks

- **Disconnected.** Re-run the whole notebook. It reads back what is on Drive and continues.
- **Out of memory on the modern arm.** Expected risk: the A100 is 40 GB and Ampere, which has no native
  FP8, and `Qwen/Qwen3.8-27B-FP8` is 30.9 GB of weights. The notebook records the failure in
  `modern_arm_failures.txt` and carries on with the Gemma model alone. That is the pre-registered
  behaviour — **do not substitute a different model.**
- **A judge's unparsed rate is above 5%.** `PREREG.md` §12 says that model is reported as broken, not
  treated as a detector that flags nothing. Tell me and stop.
- **Past 7 A100-hours.** Stop and report, whatever state it is in.

# How to run kill_v2 on Colab

Generated by `../src/make_notebook.py`. Each notebook embeds the source it needs, so upload the `.ipynb`
and nothing else. Everything writes to **`MyDrive/label_error_crc/kill_v2/`** — v1's folder is never
touched, and the judge notebooks assert that before writing a byte.

**Do not start until `PREREG.md` is approved and committed.**

Budget: **4.1 GPU-hours expected, 6.5 worst case**, hard stop **7**. Colab bills session time, so **close
each session the moment its notebook prints DONE**.

All GPU notebooks default to the **G4 runtime** (Blackwell, ~96 GB). Fallback: H100. On H100, if
`judge_gemma4` will not fit, switch it to the pre-registered fallback model named in its first cell.

## The order

| # | Notebook | Runtime | Parallel? | Expected | What to watch |
|---|---|---|---|---|---|
| 1 | `judge_gemma4.ipynb` | **G4 GPU** | all three together | ~1.2 h | first-token check, then the smoke check |
| 1 | `judge_qwen38.ipynb` | **G4 GPU** | " | ~1.0 h | thinking is off; first-token check must pass |
| 1 | `judge_mistral4.ipynb` | **G4 GPU** | " | ~1.6 h | largest download (70.8 GB) |
| 2 | `analysis.ipynb` | **CPU, most cores you can get** | alone | ~30–45 min | no GPU; prints core count first |

Step 1 is three **separate Colab sessions running at the same time**. They write to different files in the
same Drive folder and never read each other's.

For step 2, pick the runtime with the **most CPU cores** — the replicate cell is CPU-bound and parallel over
seeds. A TPU v6e-1 runtime has 44 cores and is a good choice even though no TPU is used. The first cell
prints `nproc` so you can confirm what you got.

## Click by click

**Each judge notebook (do these three first, in parallel):**

1. File → Upload notebook → pick `judge_gemma4.ipynb`.
2. Runtime → Change runtime type → **G4 GPU** → Save.
3. Runtime → **Run all**.
4. The first cell installs pinned dependencies and then **restarts the runtime on purpose**. This is
   expected, not a crash. When it reconnects: Runtime → **Run all** again. The install is cached and skipped.
5. Watch for three things, in order:
   - a version block showing `vllm 0.31.0`, `transformers 5.x`, the GPU name and its memory;
   - `first-token check PASSED (8/8)` — if it stops here the model is reasoning instead of answering, which
     is what killed v1's Qwen arm. **Stop and report; do not edit the prompt.**
   - `SMOKE CHECK <name>: PASS, continuing automatically` after the first 512 rows.
6. Let it run to `JUDGE PASS DONE` then `PROBABILITY PASS DONE`.
7. **Close the session.** Repeat for the other two notebooks.

**The analysis notebook (after all three judges have finished):**

1. File → Upload notebook → `analysis.ipynb`.
2. Runtime → Change runtime type → **CPU** (or a TPU runtime purely for its 44 cores) → Save.
3. Runtime → **Run all**. Nothing to paste: the pre-registration blob hash is already in the notebook.
4. It prints the per-detector table, the capture patterns, the Redux estimates, the empirical coverage over
   200 replicates, the four GO conditions and a verdict, and saves `analysis_summary.json` to Drive.

## What to paste back

From the analysis notebook: everything from `per detector on Redux` to `VERDICT:`. Plus, from each judge
notebook, the version block and the smoke-check block. If anything stopped early, paste the stop message
verbatim rather than a description of it.

## If something breaks

- **Disconnected.** Re-run the notebook. It reads back what is on Drive and continues from the next chunk.
- **First-token check fails.** The model is thinking before answering. Stop and report. Do not change the
  prompt or the chat-template kwargs to get past it.
- **Smoke check stops the run.** Unparsed or unscored rate above 5%, or the projection passed that
  notebook's budget. Stop and report; nothing on Drive is lost.
- **`judge_mistral4` fails to load.** It uses Mistral-native format, so vLLM needs
  `tokenizer_mode/config_format/load_format = "mistral"` — already set in the notebook. If it still fails,
  paste the error; the pre-registered fallback is to run with three detectors (D1, D2, D4), which the
  simulation covers.
- **Past 7 GPU-hours.** Stop and report, whatever state it is in.
